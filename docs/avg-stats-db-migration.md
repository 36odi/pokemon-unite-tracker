2. SQLと対象を再監査し、実DB適用の明示承認を得ます。[列追加SQL](sql/avg-stats-add-column.sql)全体を新しいSQL Editor欄に貼り付けて実行します。`IF NOT EXISTS`は使わず、同名列があればエラーで停止します。途中のエラーはトランザクションをロールバックし、アプリ公開へ進みません。
3. 型boolean・NOT NULL・既定値false、既存行のfalseを読み取りで確認します。APIでも取得上限0件の列取得が成功することを確認します。スキーマ変更後の通知は[PostgREST公式手順](https://docs.postgrest.org/en/stable/references/schema_cache.html)に基づきます。
4. 別途承認された検証用アカウント・検証データで、新規保存、編集、再読込、ゲスト移行、CSVを実測します。今回の模擬バックエンドの結果を本番DBの成功とは扱いません。
