# メダル・短縮率の計算と取り込み

確認日：2026-10-26（JST）。対象はローカル改善の第2段階。実ゲームでの計測は行っていない。

## 待ち時間短縮

`LAB_STATUS.cdr`は短縮率のパーセントポイント。`LAB_ITEMS`の「待ち時間」と、個々のメダル／ブラックの原本値は待ち時間の増減で、短縮が負。

`labStatBonusValue()`で後者だけを短縮率へ変換する。もちものとメダルは同じ変換を通す。HPの減少、妨害時間、固定ダメージ軽減には適用しない。色セットの通常ステータス補正と、短縮率に対するパーセントポイント加算も区別する。

根拠は[Wikiのステータス説明](https://wikiwiki.jp/poke-unite/ステータス)。メダルのセット効果を含めた加算と、CDRの対象がわざ1・2であることを確認した。公式に公表された計算式やゲーム内の実測とは区別する。

メダルセット作成の合計表示も、`LAB_STAT_MAP`でキーをそろえ、増加側・減少側の両方を`labStatBonusValue()`へ通す。合計欄だけ元の負の待ち時間を表示しない。ミュウツー・ミュウ・セレビィは各レアリティで正の短縮率を示す。HP等のデメリットは反転しない。`tests/lab-recheck-fixes.browser.test.js`で全257種・759通りの実表示を原本形式の値と照合する。

- アブソルLv9：20%。アクセルリストG30の3ポイントで23%、G40の3.5ポイントで23.5%。
- 基本25%＋もちもの上位3枠14ポイント＋ブラック4ポイント＋個別メダル3種1.8ポイントでも44.8%。これは入力範囲から計算した上界で、ゲーム内の上限を示す値ではない。
- ゲーム内の一般的な上限、わざ別の例外、ユナイトバフ・青バフの重ね方は今回確定していない。上限値を推測して追加せず、実際のわざの秒数やユナイトわざのCDへこの合計値を適用しない。

## 金3種とネイビー

|対象|原本・CSVの確認結果|アプリの補正|
|---|---|---|
|G28 ニャース、G29 ペルシアン、G30 カモネギ|実数0.006、表示も0.006。銅・銀は実数0.003／0.005で表示0.3%／0.5%。CSVも金だけ0.006|金の急所率を0.6ポイントへ限定補正|

金の標準値とネイビーの方向は[Wikiのメダル表](https://wikiwiki.jp/poke-unite/ポケモンサポートメダル)で照合。[Unite-DB FAQ](https://unite-db.com/faq/hidden-mathematics#Unite-Recharge)も、ネイビーによる全エネルギー獲得量の1%/2%/4%増加を記載している。

元シートの単位・表記の不整合と、アプリが表示値を単純に数値として取り込んでいたことを分ける。小数を一律100倍する処理は追加しない。`tools/normalize_lab_medals.js`を生成処理に組み込み、対象名・能力・元の値が確認範囲に一致する場合だけ補正する。将来原本が想定外の値になったら生成を止め、再確認する。全データ生成スクリプト自体は今回実行していない。

ネイビーとエナジーアンプの厳密な合成規則は未確定。計算結果でも出所別に示し、合成値や短縮秒数を作らない。A/B比較でもキーを出所別にそろえる。ゲージの補正はダメージ・回復計算へは適用しない。

ダメージ結果の要約では、防御側のゲージ補正（メダル・もちもの）を表示対象から除く。これは表示だけの整理であり、防御側の計算用ステータス、メダル/装備、保存・復元・共有条件には残す。攻撃側の表示、グレーやピンク等の未反映範囲の注意は維持する。数値・計算方法は変えていないため`LAB_CALCULATION_VERSION`は維持する。

## プラチナ限定と互換性

原本に「プラチナのみ」がある6種（ニャオハ、ニャローテ、マスカーニャ、ミライドン、ラティアス、ラティオス）だけを対象にする。原本の注記はプラチナの数値を金と同じとしている。銅・銀の値が欠けているという理由だけで、他の対象をプラチナへ推測変換しない。

- 新規選択・一括変更・保存は`platinum`。一覧には実在するレアリティだけを出す。
- この6種の旧保存にある銅・銀・金指定は、読取時にプラチナへ変換し、従来の金相当の数値を維持する。元の保存データを読取だけで書き換えない。
- 通常のメダルで欠けているレアリティは、別の値で埋めない。不明なメダル名は削除しない。
- 対戦記録、端末プリセット、計算条件、旧共有リンクは同じ表示規則を使う。8枠・10スロット形式、名前、原本スナップショットは維持。

## 計算条件の版

`dataVersion`の指紋に`LAB_MEDAL_SETS`と`LAB_CALCULATION_VERSION`を加えた。計算方式だけを変えた場合も後者を更新する。旧形式schema 1は読み続け、保存当時のdataVersionを保持して、現在のデータで再計算する案内に使う。過去の計算式を再現するものではない。

共有リンクを初めてゲストで読み込むと、プリセットの初期読込が後からメダル選択を消していた。初期読込の完了を待ってから条件を復元するよう是正した。実DBを使わず、新規ブラウザーへの旧リンク読込で確認した。

取得資料・SHA一覧・画面・検査結果は`work/lab-improvement-implementation-20261026/stage2/`。再生成検査用の原本CSVは`tests/fixtures/lab-medals-source-20261026.csv`。

## 条件付き効果と単位（第3段階）

`labStatMeta()`が、単位・条件付きか・計算範囲の注記を返す。数値を表示専用の文字列へ変換せず、基本値と条件付き効果を表示時に分ける。非戦闘時の移動速度は％、妨害持続時間は％の増減、ネイビーはゲージ獲得量の％、グレーは固定量。既存の11色データと第2段階の取得資料を再利用し、ここでは原本を再取得・変更していない。

イエローを通常の移動速度へ加算せず、ピンクから妨害の秒数を生成しない。グレーは負の固定量（5枚で-6）を保持するが、適用順序・対象外・ヒット単位・最低値が未確認のため、わざ・通常攻撃・もちもの追加ダメージには未反映。その旨をメダル作成、ステータス、ダメージ結果に表示する。ネイビーとアンプの合成は引き続き未計算。

## 防御側メダルと共有（第3段階）

攻撃側とは独立した選択と復元用スナップショットを持つ。防御側のレベル別基本値、個別メダルのレアリティ別増減、色セット補正を同じ共通計算へ渡す。青/紫6種は防御/特防の基本値の8%分と、個別の固定増減を加える。攻撃側の選択は流用しない。未選択は従来の計算を維持する。

schema 1の任意フィールド`defenseMedal`（slots/raritiesのみ）を追加。欠けている旧保存・旧ペイロードはnullへ補完し、元保存を読むだけでは書き換えない。壊れた防御側指定・未知のメダルは適用を止める。表示用の名前など個人情報を共有ペイロードへ含めない。プリセットの変更・削除後も保存条件の中身から復元する。

もちものA/B比較では、ポケモン、レベル、攻撃側と防御側のメダル、相手、選択わざを共通条件として使う。相手のメダル変更はA/B両方へ適用し、その仕様を比較欄へ明記する。Aだけ相手の古いメダルを持つ方式ではない。

`LAB_CALCULATION_VERSION`は`2026-10-26.2`。実装確認、原本取得、数値照合、ゲーム版の記録は`data/lab-calculation-verification.json`。不明なゲーム版はnullとする。

## 表示上の型と更新日（第4段階）

ストライクはラボ専用の型関数でバランス型へ補完する。[公式のハッサム紹介](https://unite.pokemon.com/en-us/pokemon/scizor/)はAll-Rounderとし、Scyther Lv1からの分岐を同ページに掲載している（2026-10-26閲覧）。対戦記録用のPOKEMON_DATAへは追加しない。

「最終更新日」は、当該ポケモンの収録説明・注記の確認日。個別のreference.checkedAtを優先し、ない場合は説明メタデータの確認日を使う。全ステータス・係数がその日に全件照合されたことや、ゲームの更新日を表すものではない。数値の取得・照合記録は上の内部記録へ分ける。出典リンクや削除済み3項目は画面へ戻さない。
