# 対戦記録のメダルセット：DB変更の手順

**未適用。** アプリ v5.56（SW v82）は、この列が無くても動作します（メダルセット欄を出さず、記録・読込は従来どおり）。列を追加すると、ログイン中の利用者にもメダルセット欄が表示されます。ゲストは列に関係なく記録できます（端末内保存）。

## 変更内容

`public.battles` に `medal_set jsonb NULL` と、形と大きさの制約（オブジェクトのみ・4KBまで）を追加します。既存行はすべて NULL のまま変わりません。RLS・権限・インデックス・既存列は変更しません。行単位のRLS（所有者条件）は新しい列にもそのまま適用されます。

## 手順（Supabase SQL Editor）

1. **確認（読み取りのみ）**：[medal-set-preflight.sql](sql/medal-set-preflight.sql) を実行し、`medal_set` 列・同名の制約が無いこと、ユーザー定義トリガーが無いことを確認します。最後の件数を控えます。
2. **追加（1回だけ）**：[medal-set-add-column.sql](sql/medal-set-add-column.sql) 全体を新しい欄に貼り付けて実行します。既存データの件数・内容が変わった場合や、新しい列に値が入っていた場合は自動で取り消されます。
3. **確認**：最後の SELECT で `records` が手順1と同じ、`with_medal_set` が 0 であることを確認します。
4. **アプリの確認**：ログインした状態で、詳細設定に「メダルセット」欄が出ること、記録・編集・履歴・CSV・分析に反映されることを確認します。

**順序**：DB変更とアプリ公開はどちらが先でも壊れません。ただしDB変更前は、ログイン中の利用者にはメダルセット欄が出ません。
また、DB変更前にゲストでメダルセット付きの記録を作った人がログインした場合、ゲストデータの移行は中止され（データは端末に残ります）、DB変更後のログインで改めて移行できます。

## 戻し方

推奨はアプリを旧版へ戻し、列と記録済みのメダルセットを残す方法です。列削除は [medal-set-rollback.sql](sql/medal-set-rollback.sql)（誤実行防止のためコメント化）を、退避と明示承認の後にのみ使います。
